# 模擬器校準表

實機量測結果的彙整表，報告直接引用。[ADR-0001](../adr/0001-policy-level-simulation-as-measurement-instrument.md) 提議（尚未定案）實機不產生 relay 策略的比較結果，只產生這份校準表，交給 JVM 模擬器（串接 N 個真實 `PacketRelayManager` 的模擬器）使用。ADR 列出的最低需求是每跳延遲、單鏈路送達率、最大同時連線數；下表另外補上模擬器建立拓撲與鏈路模型時需要的參數。不做模擬器時，這些數字仍是實地可用性的結果。

實驗完成後填入「值」與「信賴區間／分布」兩欄，並註明資料來自哪幾個 run_id。

## 不由實機提供的參數

以下參數由模擬器的實驗設計決定，不從實機量測，記錄在此是為了避免被誤認為「漏量」：

- **節點數 N 與空間密度**：實機上限為 7，模擬器掃描到 N = 500。
- **Status／Severity 的分布與 Severity Inflation 比例**：屬於實驗軸，見 [ADR-0002](../adr/0002-severity-is-a-derived-transport-hint.md)。
- **分片行為**：ADR-0001 明定不模擬分片。Health Report 的 Broadcast Tier 約 20 bytes，本身也不會分片。

## 已知限制（須寫入報告）

- 7 支手機的型號各不相同，裝置差異（σ_dev）會混入鏈路參數中。以 E1-A 的排名交錯排列可以降低偏差，但無法完全消除。
- 所有距離類參數都是在 BALANCED 模式（廣播發射功率 MEDIUM）下量的；PERFORMANCE 與背景模式的距離不同，見 E4-B2。
- 飽和負載是用約 20 bytes 的小封包量的；較大的封包（例如私訊、媒體）的飽和點會更低。
