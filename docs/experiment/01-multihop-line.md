# E1 多跳線性鏈：單跳距離與多跳最大距離

## 目的

1. 量出開闊環境下的**可靠單跳距離 `d_rel`** 與**最大單跳距離 `d_max`**。後續所有實驗的間距都以此為基準。
2. 量出 7 支手機排成線性鏈時，Health Report 能送多遠，以及每多一跳會增加多少延遲與遺失。
3. 驗證 TTL 對可達跳數的限制。

## 依程式碼推得的預期（實驗要驗證或推翻）

- 節點數 ≤ 10 時，`PacketRelayManager` 的 relay 機率為 1.0，鏈上每一支手機都會轉發。
- Health Report 送出時 TTL = 3。依程式碼推算：N1 發出 → N2 收到時 TTL 3 → N3 收到 2 → N4 收到 1 → N5 收到 0，之後不再轉發。**預期 N1 的 Health Report 最遠到 N5（4 跳），N6、N7 收不到。** 如果 N6、N7 收到了，代表實際拓撲中有跳過節點的直連（間距太近）。
- TTL 7 的封包（Announce，以及發送器設為 TTL 7 時）可以涵蓋整條 6 跳的鏈。
- 線性鏈上，唯一的路徑串起所有鏈路，因此預期端到端送達率 ≈ 各跳送達率的乘積。若實測明顯較高，代表存在跳過節點的冗餘鏈路。

## 場地

- 筆直、無遮蔽、長度 ≥ 150 m。候選地點：操場直線跑道、河濱自行車道、空曠停車場的對角線。
- 若 `d_rel` 很大（例如 80 m），7 機鏈長約 6 × 0.8 × 80 ≈ 380 m，需要更長的場地。可以改成沿道路的 L 形佈置，但轉角處必須無遮蔽。
- 量距：50 m 以內用捲尺，以上用測距輪或雷射測距儀；Google 地圖只用在 ≥ 100 m、兩端都是地標的點位，並記錄估計誤差。不要用手機 GPS。工具比較見 [00 §3.7](00-setup-and-instrumentation.md#37-點位記錄與量距)。
- **開始前先把點位量好並做記號**（粉筆、三角錐），實驗時直接走到記號站好。
- 避開高壓電塔與大型金屬圍籬。記錄地面材質（草地／柏油／水泥）。

## E1-A 裝置差異標定（約 40 分鐘）

7 支手機的晶片與天線不同，訊號強度可能相差好幾 dB。先排出強弱順序，再決定 E1-B 用哪兩支、E1-C 怎麼排列。

**步驟**

1. 任選一支作為參考機 R（記錄是哪一支），固定在 0 m。
2. 其餘 6 支逐一放在距離 R 20 m 處（LOS、1.2 m 高）。
3. 每一支：
   1. 打開藍牙並開始計時，記錄到 `LINK_UP` 的 T_disc。
   2. 連線後等 30 s，記下這 30 s 的起訖時間；雙向 RSSI 的中位數事後從兩邊 `exp.csv` 的 `RSSI` 列算（現場畫面不顯示 RSSI）。
   3. R → X 送 20 筆，X → R 送 20 筆（間隔 1 s，TTL 3）。
4. 依雙向 RSSI 的平均值排出強弱。

## E1-B 單跳距離標定（約 60 分鐘）

**手機**：E1-A 排名在中間的兩支。P 固定在 0 m，Q 移動。

**距離序列**：5、10、20、30、40、50、60、70、80、100、120、150 m……

在 PDR 開始下降的區段，改以 5 m 為間隔補點。

**停止條件**：連續兩個距離的 PDR < 50%，或 120 s 內沒有 `LINK_UP`。

**每個距離的步驟**

1. Q 關閉藍牙，走到定點後站好。記錄員在 [stations.csv](templates/stations.csv) 開一列，寫上距離、量距方式與 `t_start`；離開這個點位時填 `t_end`。**沒有這兩個時間，事後無法把 log 對到距離。**
2. Q 打開藍牙並開始計時，記錄 T_disc。在 10 m、0.5·d_rel、d_rel 這三個距離，T_disc 要重複 5 次（關藍牙 → 開藍牙），其餘距離量 1 次即可。
3. 連線後等 30 s，記下這 30 s 的起訖時間；雙向 RSSI 的中位數事後從兩邊 `exp.csv` 的 `RSSI` 列算（現場畫面不顯示 RSSI）。
4. P → Q 送 50 筆，再 Q → P 送 50 筆（間隔 1 s，TTL 3）。
5. 從現場計數畫面確認收到的筆數，填入記錄表。

**導出值**

| 值 | 定義 |
|---|---|
| `d_rel` | 雙向 PDR 都 ≥ 95% 的最大距離 |
| `d_max` | 仍能建立 `LINK_UP` 且 PDR > 0 的最大距離 |
| 路徑損耗指數 `n` | 以 `RSSI(d) = RSSI(d₀) − 10·n·log₁₀(d/d₀)` 擬合 RSSI–距離資料，d₀ = 5 m。給模擬器的鏈路模型使用 |
| `p_link(d)` | 單鏈路送達率對距離的曲線，直接取自記錄表 |

## E1-C 七機線性鏈（每個間距約 20 分鐘）

**佈置**

```
N1 ──s── N2 ──s── N3 ──s── N4 ──s── N5 ──s── N6 ──s── N7
(來源)                                                 (末端)
```

- 依 E1-A 的排名交錯排列，避免最弱的兩支相鄰。實際的排列要記錄在 runs.csv。
- 間距 s 分四個等級：`0.5·d_rel`、`0.8·d_rel`、`1.0·d_rel`，以及 `1.2·d_rel`（只有在 1.0 時 N7 的 TTL 7 PDR 仍 ≥ 90% 才做）。

**拓撲的現實限制**：要保證「只有相鄰節點直連」，必須 `2s > d_max`。當 `d_max` 遠大於 `d_rel` 時這做不到。例如 s = 0.5·d_rel 時，N1 很可能直接連到 N3。**這是預期中的情況**，分析時以實測的鄰接表與 TTL 推算出的跳數為準，不要假設跳數等於位置差。

**步驟（每個間距）**

1. 全員就位。所有人同時打開藍牙（以口令或對講機同步），開始計時。
2. 記錄 **T_chain**：從同時開啟到 N7 的 peer 清單出現 N1 的時間（Announce 為 TTL 7，會經多跳傳到 N7）。
3. 等待 120 s 讓拓撲穩定。各位置回報自己的直連鄰居（現場計數畫面上的直連數，或事後從 `LINK_UP` 整理）。
4. N1 送 50 筆，TTL 7，間隔 2 s。
5. N1 送 50 筆，TTL 3，間隔 2 s。
6. N7 送 50 筆，TTL 7，間隔 2 s（反向）。
7. 若 N7 收到 N1 的 TTL 7 封包 PDR ≥ 90%，進入下一個間距；否則在此間距再做一次 run，確認結果後結束。

發送間隔固定為 2 s，目的是避免壅塞干擾距離量測。負載的影響交給 E3 處理。

## 指標總表

| 指標 | 子實驗 | 定義／判讀 |
|---|---|---|
| 裝置間 RSSI 差異 | E1-A | 7 支手機的強弱排名；最強與最弱相差的 dB 數 |
| `d_rel`、`d_max` | E1-B | 見 E1-B 導出值 |
| RSSI–距離曲線、路徑損耗指數 `n` | E1-B | 戶外 LOS 的鏈路模型 |
| `p_link(d)` | E1-B | 單鏈路送達率對距離 |
| T_disc(d) | E1-B | 發現時間是否隨距離變長 |
| 端到端 PDR(h) | E1-C | 對照 `∏ p_link`：較高代表有冗餘鏈路，較低代表跨跳的遺失彼此相關（例如中間節點的佇列） |
| L(h) p50／p95、ΔL | E1-C | 每跳延遲是模擬器校準表的核心參數 |
| **多跳最大距離 D_max** | E1-C | PDR ≥ 90% 的最遠節點與 N1 之間的地面距離。這是本實驗的主要結果 |
| 最大有效跳數 h_max | E1-C | PDR ≥ 90% 的最大跳數 |
| TTL 3 的可達範圍 | E1-C | 驗證「Health Report 最遠 4 跳」的推算 |
| T_chain | E1-C | 7 機同時開機到端到端可見的時間 |
| 方向不對稱 | E1-C | PDR(N1→N7) 與 PDR(N7→N1) 的差 |
| 鏈路穩定度 | E1-B、E1-C | 每個 run 的 LINK_DOWN 次數 |

## 產出

- `d_rel`、`d_max`、`n`、`p_link(d)`、ΔL → [calibration-table.md](calibration-table.md)
- D_max、h_max、TTL 3 的可達範圍 → 實地可用性結論。如果 TTL 3 確實只到 4 跳，而 E2-C 顯示「從建物內送到戶外」需要更多跳，就構成調整 Health Report TTL 的依據。
