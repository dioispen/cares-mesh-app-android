# E2 建築物穿透

## 目的

1. 量化常見障礙（牆、樓板、門窗、人體、口袋、瓦礫）對 BLE 單跳的衰減，以及障礙後還能傳多遠。
2. 找出「受困者在建物內」的 Health Report 需要幾個中繼才能送到戶外，並確認 TTL 3 是否足夠。

## 場地需求

- 一棟 ≥ 4 層的 RC 建築，最好有地下室（例如地下停車場），並有樓梯間。
- 建物內要能找到：輕隔間、磚牆、RC 牆、玻璃門窗、金屬門或防火門。
- 事先畫好各樓層的平面草圖，標上所有點位編號（W0、W1……、F1、F2……）。

## 手機與控制

- E2-A、E2-B、E2-D 使用同一對手機：E1-A 排名在中間的兩支，以 S（發送）與 R（接收）表示。每個條件都要交換角色再做一次，量出方向不對稱。
- E2-C 使用 7 支。
- **對照組必須在同一棟建物內量**（走廊 LOS）。室外 E1-B 的數據不能直接拿來比，因為室內的多重路徑效應會讓 RSSI 偏高。
- 每個條件：雙向 RSSI 取 30 s 中位數（記下起訖時間，事後從 `exp.csv` 的 `RSSI` 列算）、雙向各 50 筆（間隔 1 s，TTL 3）、T_disc 量 1 次。

**佈置**：S 固定在牆的一側、距牆 1 m；R 在另一側，與 S 的直線距離固定為 `d_test = 10 m`。

| 條件 | 障礙 |

| W1 | 1 道輕隔間（石膏板／木板） |
| W2 | 1 道磚牆 |
| W3 | 1 道 RC 牆 |
| W4 | 2 道 RC 牆 |
| W5 | 玻璃門或窗（關閉） |
| W6 | 金屬門／防火門（關閉） |

## E2-B 垂直穿樓板（約 45 分鐘）

**佈置**：S 固定在 1F；R 在 S **正上方**（同一平面位置）逐層往上：2F、3F、4F……，地下室則往下：B1、B2。

分成兩組位置各做一次：

- **房間中央**：只穿樓板。

R 量到 120 s 內沒有 `LINK_UP` 就停止往上。

## E2-C 跨樓層多跳中繼：受困情境（約 60 分鐘）

**情境**：受困者在地下室（或頂樓）最內側的房間，救援指揮點在建物外 20 m 處。

```
[N1 受困者：B1 最內側] → N2 → N3 → ... → [N7 戶外救援者：建物外 20 m]
                       （中繼沿逃生動線放置）
```

**中繼放置法（逐步延伸）**

1. N1 開始持續發送：TTL 7、間隔 2 s。
2. 持 N2 的人從 N1 出發，沿逃生動線走。每到一個轉角或樓梯平台就停下，看現場計數畫面：最近 20 s 內收到 N1 的封包 ≥ 9 筆，就繼續往前；不到就退回上一個成功點，放置 N2。
3. N3、N4……依序以同樣方法從上一個中繼延伸。
4. 每放下一個中繼，就先確認 N7 能不能直接收到最後一個中繼的封包。能的話，停止增加中繼。
5. 中繼全部就位後，等 120 s，正式量測：
   - N1 送 50 筆 TTL 7（間隔 2 s）。
   - N1 送 50 筆 TTL 3（間隔 2 s）。

## E2-D 遮蔽與擺放情境（約 45 分鐘）

**佈置**：在空曠處（戶外，或大廳這類大空間）固定距離 `d = 0.5·d_rel`。R 一律手持 1.2 m，只改變 S 的狀態。

| 條件 | S 的狀態 | 模擬情境 |
|---|---|---|
| B0 | 手持 1.2 m（對照） | — |
| B1 | 褲子前口袋，人站立面向 R | 手機放在口袋 |
| B2 | 背包內，背對 R | 手機在背包裡 |
| B3 | 平放地面（0 m），螢幕朝上 | 倒地的受困者 |
| B4 | 地面，上方覆蓋約 20 cm 的紙箱與書本 | 被非金屬瓦礫掩埋 |
| B5 | 金屬置物櫃或鐵櫃內，櫃門關閉 | 金屬遮蔽 |
| B6 | 手持 1.2 m，但兩機正中間站一個人 | 人群遮擋 |

**選做**：B3（地面）額外做一次縮短版的距離掃描（5、10、20、30 m……），量出**地面的 d_rel**（點位一樣記進 stations.csv）。倒地或受困的手機貼近地面，可用範圍可能比手持小很多，這會直接影響救援時需要的中繼密度。

## 指標總表

| 指標 | 子實驗 | 定義／判讀 |
|---|---|---|
| 各障礙的衰減 ΔRSSI | E2-A、E2-B、E2-D | 同距離下與對照組的 RSSI 差。給模擬器的「障礙衰減」參數 |
| 障礙下的 PDR | 全部 | 衰減是否已經大到開始掉封包 |
| 牆後可靠距離 | E2-A | 隔一道牆後，還能可靠傳多遠 |
| 可穿透的樓層數 | E2-B | 房間中央與樓梯間分開記錄 |
| 最少中繼數 N_relay | E2-C | 從受困點到戶外最少需要幾個中繼 |
| 受困情境的端到端 PDR、L、h | E2-C | 對照 E1-C 同跳數下的結果，看室內是否比較差 |
| TTL 3 是否足夠 | E2-C | 本實驗最重要的設計結論 |
| 地面的 d_rel | E2-D（選做） | 倒地或受困手機的可用範圍 |
| 方向不對稱 | 全部 | 交換 S、R 後的差異 |

## 產出

- 各障礙的 ΔRSSI → [calibration-table.md](calibration-table.md) 的「障礙衰減」列。
- N_relay 與「TTL 3 是否足夠」→ 實地可用性結論。這是 Health Report TTL 設計的直接證據。
- 地面 d_rel → 救援時中繼部署密度的建議。
